# fix-bug 技能

## 何时使用

当发现缺陷或收到 bug 报告时使用本流程。

## 执行步骤

1. **理解问题**：
   - 阅读缺陷报告，确认现象、影响范围和复现环境。
   - 如信息不足，补充询问或复现。
2. **复现缺陷**：
   - 在本地或测试环境复现问题。
   - 记录复现步骤和关键日志。
3. **定位根因**：
   - 使用日志、调试工具、断点定位问题代码。
   - 区分是代码缺陷、配置问题还是数据问题。
4. **制定修复方案**：
   - 评估修复影响范围。
   - 如涉及架构或接口变更，先更新设计文档。
5. **实现修复**：
   - 先编写复现测试，再修改代码。
   - 保持最小改动原则。
6. **验证修复**：
   - 运行复现测试确认缺陷已修复。
   - 运行回归测试确保未引入新问题。
7. **更新记录**：
   - 更新 `project-control/backlog.md`。
   - 如有必要，更新 `project-control/decisions.md`。

## 验收标准

- [ ] 缺陷已在本地/测试环境复现。
- [ ] 已编写复现测试。
- [ ] 修复代码通过 lint/type-check。
- [ ] 复现测试已通过。
- [ ] 相关回归测试已通过。
- [ ] PR 已创建并通过 CI。

## 注意事项

- 修复前先确认缺陷影响范围，避免过度修复。
- 不要只修复表象，优先找到根因。
- 涉及数据修复时，需提前备份。
