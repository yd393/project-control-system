# release 技能

## 何时使用

当准备将版本发布到测试环境或生产环境时使用本流程。

## 执行步骤

1. **版本确认**：
   - 确认发布版本号，符合语义化版本规范。
   - 确认该版本包含的变更范围。
2. **变更日志**：
   - 更新 `CHANGELOG.md` 或发布说明。
   - 列出新增功能、修复项、破坏性变更。
3. **代码冻结**：
   - 停止向发布分支合并无关变更。
   - 从主分支创建 `release/<版本号>` 分支。
4. **回归测试**：
   - 运行完整的自动化测试套件。
   - 执行核心业务流程的手工回归测试。
5. **配置检查**：
   - 确认环境变量、数据库迁移、依赖服务已就绪。
6. **部署执行**：
   - 按部署文档执行发布。
   - 监控系统、日志、错误率。
7. **部署验证**：
   - 执行冒烟测试。
   - 验证关键功能可用。
8. **回滚预案**：
   - 确认回滚步骤和回滚触发条件。
   - 保留上一版本镜像或构建产物。

## 验收标准

- [ ] 版本号已确认并打 tag。
- [ ] 变更日志已更新。
- [ ] 全量测试已通过。
- [ ] 配置和迁移已就绪。
- [ ] 部署已完成且服务健康。
- [ ] 冒烟测试已通过。
- [ ] 回滚预案已准备。

## 注意事项

- 避免在业务高峰期发布。
- 发布过程中保持沟通，及时同步状态。
- 出现问题优先保障服务可用，必要时立即回滚。
