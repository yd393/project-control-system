# add-api 技能

## 何时使用

当需要为项目新增一个 API 接口时使用本流程。

## 执行步骤

1. **需求确认**：明确接口的输入、输出、使用方和业务场景。
2. **接口设计**：
   - 确定 HTTP 方法、URL、请求参数、响应格式。
   - 定义错误码和错误信息。
   - 更新 `.ai/context/architecture.md` 中的接口约定。
3. **代码实现**：
   - 按照分层架构实现 Controller → Service → Repository。
   - 遵循编码规范 `.ai/rules/coding.md`。
4. **单元测试**：为 Service 和 Controller 编写单元测试。
5. **集成测试**：覆盖接口完整调用链。
6. **文档更新**：更新 API 文档（如 OpenAPI/Swagger、README）。
7. **代码审查**：提交 PR 并经过审查。

## 验收标准

- [ ] 接口设计文档已记录。
- [ ] 代码已实现并通过 lint/type-check。
- [ ] 单元测试覆盖核心逻辑。
- [ ] 集成测试覆盖接口调用链。
- [ ] API 文档已更新。
- [ ] PR 已创建并通过 CI。

## 注意事项

- 新增接口前确认是否需要版本控制。
- 注意接口的权限和认证要求。
- 避免破坏现有 API 的向后兼容性。
