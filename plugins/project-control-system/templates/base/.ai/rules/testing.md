# 测试规范

## 测试覆盖率要求

- 单元测试覆盖率不低于 80%。
- 核心业务逻辑覆盖率不低于 90%。
- 关键路径必须包含集成测试。

## 测试类型

| 类型 | 范围 | 工具/框架 | 要求 |
|------|------|-----------|------|
| 单元测试 | 函数/类 | Jest/pytest | 每个公共函数至少一个测试 |
| 集成测试 | 模块间交互 | Supertest/httpx | 覆盖主要接口调用链 |
| E2E 测试 | 关键用户流程 | Playwright/Cypress | 覆盖登录、核心业务流程 |

## 验收方式

- 所有测试必须在 CI 中通过。
- 新增功能必须伴随对应测试。
- 修复缺陷必须先添加复现测试，再修复代码。
- 测试应独立、可重复，不依赖外部状态。

## 测试命名

- 测试文件命名：`*.test.ts` 或 `test_*.py`。
- 测试用例名称应清晰描述场景和预期：`should return 404 when user not found`。

## 禁用事项

- 禁止在测试中使用真实的生产数据库或外部服务。
- 禁止跳过失败的测试而不记录原因。
