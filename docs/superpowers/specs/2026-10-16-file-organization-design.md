# 项目总控：文件整理能力设计

状态：交付 Claude Code 的设计方案，尚未实现。用户要求独立设计并由 Claude Code 执行；本文不代表已经安装、发布或验证功能。

## 目标与判断

在现有项目总控插件内提供 File Organizer 的实用能力：盘点、分类建议、内容查重、移动、重命名、归档、操作记录和维护建议。继续用一个技能入口，根据任务按需加载文件整理手册。

核心判断：文件的位置与生命周期属于项目管理，但文件扩展名和修改日期不足以决定其业务用途。由模型理解语境和提出映射，由只读脚本提供事实，再按已授权范围逐项执行。这比直接拼接原技能更适合现有项目总控。

比较过三种做法：

| 做法 | 判断 |
|---|---|
| 将原技能全文并入主 SKILL.md | 内容膨胀，且类型分类、日期归档规则可能覆盖项目语义，不采用 |
| 独立安装第二个整理技能 | 形成两套入口与规则，不符合整合需求，不采用 |
| 一个入口、按需整理手册、只读辅助脚本 | 采用；沿用总控规则，执行路径短，事实可测试 |

## 工作模式

### 项目模式

目标是具体项目时，先读该项目的 AGENTS.md 和已有管理规则。结构、正式交付物和当前有效版本以项目事实为准。整理不自动初始化缺失的总控骨架；只有用户需要建立总控时才调用现有初始化脚本。

AGENTS.md、project-control/、.ai/、.opencode/、.git/、源代码、构建与依赖文件不参与通用按类型重排。修改这些区域属于明确的项目重构任务。可在用户指定的资料、草稿、导出目录内整理，但仍需检查引用。

### 普通目录模式

适用于下载、桌面、照片和一般资料目录，不创建 AGENTS.md、project-control/ 或 .ai/。按用途优先、类型其次、日期辅助提出结构。照片按拍摄时间整理仅在已有工具能可靠提取 EXIF 时采用；否则注明使用文件修改时间，不把它当作拍摄日期。

扫描普通目录时，发现嵌套项目（含 .git 文件/目录、AGENTS.md、project-control/、.ai/ 或 .opencode/）就将其作为边界，报告路径，不递归拆散。用户要求整理其中某个项目时重新以该项目为根启动任务。跨项目合并、整个项目搬家不纳入普通散文件整理。

## 完整工作流

1. **确定范围**：明确目标目录、项目或普通目录模式、排除项和目标；从用户指令与现有规则可推断的信息不重复询问。目标不明确时先只读盘点。
2. **收集事实**：扫描文件数量、逻辑大小、扩展名、修改时间范围、较大文件、被跳过的项目与扫描错误。仅在需要查重时计算哈希。
3. **形成判断**：将文件分为保留、移动、重命名、归档、待确认。同名不是重复，内容相同也可能有不同职责；不因“更旧”“名字不好看”认定可以删除。
4. **生成具体清单**：每项记录源路径、目标路径、动作、理由、引用影响、授权依据和状态。名称保留有意义的版本、日期和交付标识。默认不自动添加编号解决冲突，先给出合理的新命名。
5. **执行授权范围**：用户已明确批准的具体映射或命名规则可直接执行。只有笼统“整理一下”且结构需选择时，展示清单后一次确认。删除、覆盖、跨项目合并单独确认；不能把批准移动理解为批准删除。
6. **逐项执行与记录**：确认源文件未变化、目标不存在（含大小写冲突）、路径无符号链接越界。移动保留修改时间；使用工具的独占创建或不覆盖模式，不能只依赖事前 exists 检查。跨文件系统移动先复制、验证内容与元数据，再移除源；无法保障时保留源并报告。每项操作前记录 pending，完成后记录 done；失败即停，报告已完成与剩余项，不声称整批原子成功。
7. **检查引用**：移动前搜索相关路径和文件名，移动后复查 Markdown 本地链接与已知配置引用；对明确可识别的引用在授权范围内更新。报告搜索范围、已修复和无法确定的引用。不要承诺通用解析代码、数据库、外部服务或所有 Markdown 语法。
8. **交付**：汇总完成项、未完成项、仍待决定项、记录位置和维护建议。项目任务在现有总控中补充简短状态/交接链接；建议 Git 留档，未经授权不提交。普通目录只提供轻量记录，不生成项目管理层。定期整理属于建议，不自动创建定时任务。

## 记录与恢复边界

每次任务记录包含：run_id、根目录、模式、排除项、扫描是否完整、逐项源/目标映射、操作前 size/mtime_ns、需要时的 SHA-256、理由、授权依据、pending/done/failed 状态、引用编辑摘要与恢复注意事项。

已有 project-control/ 的项目放到 project-control/operations/<run_id>.md；普通目录默认放到 <root>/.file-organization/<run_id>.md。这是实际整理开始后按需创建的审计记录，不是扫描的副作用。若目标只读，将记录放入当前可写工作区并明确位置。

路径映射用于辅助恢复，不承诺“一键回滚”。恢复前检查目标内容是否被后续编辑、原路径是否占用、关联引用是否改变；冲突需人工判断。删除不在默认流程里，也无法靠日志恢复。Git 无法替代未跟踪文件备份。

## 只读扫描器契约

新增 scripts/inventory_files.py，Python 3.10+，仅标准库，macOS/Linux 优先；避免 GNU find、md5 平台命令差异。

```sh
python3 scripts/inventory_files.py /path/to/root --json
python3 scripts/inventory_files.py /path/to/root --duplicates --json
python3 scripts/inventory_files.py /path/to/root --exclude 'exports/**' --json
```

- 根目录必须存在且是目录，规范化后报告绝对路径；允许用户明确指定的根路径本身是符号链接，解析后固定根边界。内部符号链接只报告，不跟随。
- --exclude 可重复，使用根目录相对 POSIX 路径 glob；实现与文档明确采用 pathlib.PurePosixPath.match 语义，匹配目录后剪枝。例如 `exports` 排除整个目录，`*.tmp` 排除任意层的该后缀。不要宣称支持完整 gitignore 语法。
- 默认剪枝目录：.git、.hg、.svn、node_modules、.venv、venv、__pycache__、.file-organization；任何层均生效。忽略 .DS_Store 文件。不默认排除所有隐藏文件。嵌套项目边界额外剪枝；根本身可为项目，不因此跳过全部内容。
- 不读取文件正文用于分类，不执行目录中的脚本，不写报告文件；JSON 输出至 stdout，由调用方选择存放位置。
- 文件按相对路径排序。扩展名转小写；无扩展名用空字符串。logical_bytes 是所有已扫描普通文件的 st_size 之和，不能称作实际磁盘占用。
- 开启 --duplicates 后先按大小分组，再分块 SHA-256；仅对大小相同且至少有两个不同 inode 的候选计算。哈希前后核对 size、mtime_ns、device、inode；变化/不可读记录错误并排除重复结论。
- 相同 device/inode 的硬链接另报 hardlink_groups，不作为独立可释放空间。空文件可构成内容重复组，但候选释放字节为零。重复组是内容相同候选，不是删除许可。
- 同名不同内容不进重复组。重复组以 size、sha256、paths 表示；estimated_reclaimable_bytes 按每组独立 inode 数减一乘 size 计算，是逻辑估算，未考虑 reflink、压缩、稀疏文件与业务保留需求。
- 权限错误、文件消失、哈希中发生变化均记录具体相对路径与错误类型，继续扫描其他文件，complete=false；不把未扫描部分当作空目录。
- 无效根/参数退出 2，完整扫描退出 0，部分扫描退出 1。JSON 模式错误也输出统一对象，stdout 不混杂提示，stderr 可输出诊断。参数解析失败沿用 argparse 的 stderr 和退出 2，不强行伪造报告。

JSON schema_version=1，固定顶层字段：root、complete、summary、files、duplicate_groups、hardlink_groups、skipped、errors。summary 包含 file_count、logical_bytes、extensions（每项 count/bytes）、oldest_mtime_ns、newest_mtime_ns、estimated_reclaimable_bytes。files 每项包含 path、size、mtime_ns、device、inode。skipped 每项包含 path/reason；errors 包含 path/kind/message。无文件时两个时间字段为 null；未启用查重时 duplicate_groups=[]、estimated_reclaimable_bytes=null。文本模式复用同一结果，展示概览与最大的前 10 个文件。

## 内容组织与范围

- 主 SKILL.md 增加文件整理触发场景与模式路由；在“工程骨架初始化”前明确只有搭建总控任务才走初始化。详细工作流放 references/file-organization.md，避免主入口继续膨胀。
- agents/openai.yaml、插件描述和两份 README 同步呈现新增能力；主版本号留在发布阶段统一决定。本轮不改 marketplace 路由。
- 修正内层 README 的旧 docs/00_总控 布局和不存在的 --layout 示例，按真实脚本使用 project-control/。
- 不增加第二个技能，不改现有脚手架生成集，不让结构检查强制要求整理日志。
- 暂不实现通用 move/apply/undo 引擎、自动删除、语义相似文件识别、跨项目合并、监控服务或自动引用重写器。移动等操作由技能指导执行工具完成，不能将“无批量引擎”描述为“不支持整理”。

## 验收场景

1. 下载目录含散落 PDF、照片和完整项目：提出可执行整理清单，项目保持边界，不创建总控骨架。
2. 项目资料目录含链接引用：移动前识别引用，移动后更新可确认引用并报告覆盖范围，不按类型移动核心配置。
3. 同名不同内容、异名同内容、硬链接、空文件同时存在：查重分类正确，不承诺删除收益。
4. 文件在哈希时变化、目录不可读：报告不完整与具体原因，不输出虚假的全部完成。
5. 目标重名、大小写冲突、符号链接、跨卷移动或操作中断：停止相关动作，保留可判断的记录，不静默覆盖。
6. 已授权明确映射：不重复索取相同批准；未授权删除：仅列候选。
7. 原有 base/Python/TypeScript 脚手架仍可生成且通过已有结构检查。
